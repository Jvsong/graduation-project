当前关键配置建议保持如下：

- `environment.base_url = http://localhost:3000`
- `environment.api_base_url = http://localhost:8083/api`
- `report.output_dir = ./reports`
- `test.screenshot_path = ./reports/screenshots`
- `ai.api_base = https://api.openai.com/v1` 或你的 OpenAI 兼容平台地址
- `ai.model = gpt-4.1-mini` 或兼容平台要求的模型名
- `ai.chat_endpoint = /chat/completions`
- `ai.max_retries = 2` 最大重试次数（针对可恢复错误）
- `ai.retry_delay = 1.0` 基础重试延迟（秒，采用指数退避）

说明：

- `report.output_dir` 控制报告根目录。
- HTML 测试报告会统一存放到 `reports/html/按日期/按模块/按批次时间/`。
- 失败截图会统一存放到 `reports/screenshots/按日期/按模块/`。
- AI key 建议优先通过环境变量 `OPENAI_API_KEY` 管理。
- 如果使用第三方 OpenAI 兼容平台，通常还需要同时修改 `ai.api_base` 和 `ai.model`。
- `ai.max_retries` 和 `ai.retry_delay` 控制 AI 服务调用的重试行为，针对网络波动和服务端临时错误提供自动恢复能力。

## 5.2 AI 功能增强说明

近期对 AI 分析功能进行了多项重要增强，包括：

### 5.2.1 结构化 AI 摘要输出

AI 测试摘要现在包含更丰富的结构化字段：

- `confidence_score`：AI 分析结果的置信度评分（0-1 之间）
- `trend_analysis`：趋势分析，与历史执行数据对比（如有）
- `key_findings`：关键发现摘要数组，突出最重要的测试发现
- `improvement_areas`：需要改进的领域数组（如测试稳定性、执行效率等）
- `execution_quality`：执行质量评估（excellent/good/acceptable/poor/unknown）
- 保留原有的 `summary`、`risk_modules`、`recommendations`、`rerun_suggestion`、`stability_trend`、`root_cause_summary` 字段

### 5.2.2 增强的错误处理与重试机制

AI 服务调用现在支持更稳健的错误处理和重试：

- **配置项**：
  ```yaml
  ai:
    max_retries: 2      # 最大重试次数
    retry_delay: 1.0    # 基础重试延迟（秒）
  ```
- **重试策略**：针对以下可恢复错误自动重试：
  - 429 Too Many Requests（限流）
  - 5xx 服务端错误（500, 502, 503, 504）
  - 连接超时和网络连接错误
- **指数退避**：重试延迟按指数增长（1s, 2s, 4s...）
- **错误分类**：更精细的错误分类（timeout/connection/request/unknown）

### 5.2.3 改进的降级策略

当 AI 服务不可用时，系统会自动降级：

1. **服务检测**：通过健康检查判断 AI 服务可用性
2. **本地分析**：使用基于规则的本地方案分析失败原因
3. **智能摘要**：基于测试统计数据生成本地摘要
4. **结果标记**：清晰标记分析来源（ai/service_error/heuristic/disabled）

### 5.2.4 增强的 HTML 报告展示

HTML 测试报告中的 AI 分析部分已全面增强：

- **摘要面板**：新增"执行质量"和"置信度"卡片
- **结构化展示**：
  - 关键发现列表
  - 改进领域列表
  - 失败原因分类统计
  - 趋势分析说明
- **失败分析卡片**：显示问题分类、分析来源和详细诊断信息
- **表格工具提示**：鼠标悬停显示 AI 分析的严重程度、分类和置信度

### 5.2.5 配置建议

对于生产环境使用，建议：

1. **环境变量管理**：优先使用 `OPENAI_API_KEY` 环境变量而非配置文件硬编码
2. **重试配置**：根据网络稳定性调整 `max_retries`（默认 2 次）
3. **超时设置**：适当调整 `ai.timeout`（默认 45 秒）
4. **输入长度**：通过 `ai.max_input_chars` 控制发送给 AI 的日志长度

## 7. HTML 测试报告

现在无论使用哪一种方式执行 pytest，用例结束后都会自动生成 HTML 报告，无需手动追加 `--html` 参数。

统一输出目录：

```text
F:\Desk\graduation project\reports\html\YYYY-MM-DD\模块名\HHMMSS
```

命名规则示例：

- `reports/html/2026-04-20/login/170805/login.html`
- `reports/html/2026-04-20/product/170912/product.html`
- `reports/html/2026-04-20/mark_smoke/171030/mark_smoke.html`
- `reports/html/2026-04-20/all/171155/all.html`
- 同目录下会生成配套的 `login.json`、`product.json` 等结构化数据文件

说明：

- 直接执行 `pytest ecommerce-autotest/testcases/test_login.py -vv` 时，会自动生成对应模块报告。
- 执行 `pytest` 时，会自动生成整套测试报告。
- 执行 `python run.py login`、`python run.py all` 或旧写法 `python run.py --run xxx` 时，也会生成 HTML 报告，并且同样放到 `reports/html/`。
- 如果命令里手动显式传入 `--html=...`，则以手动指定路径为准。
- 报告目录按“日期 / 模块 / 批次时间”归档，便于区分不同测试轮次。
- AI 增强报告面板会直接嵌入 HTML 报告中，并同时输出同名 JSON 数据文件。

### 7.1 AI 增强报告功能

HTML 报告中的 AI 分析部分包含以下增强功能：

#### 7.1.1 AI 测试总结面板
- **总体结论**：突出显示通过率、主要问题和稳定性评估
- **数据卡片**：展示高风险模块、回归建议、执行质量、置信度评分
- **建议处理项**：可操作的具体修复建议列表
- **关键发现**：最重要的测试发现摘要
- **改进领域**：需要重点改进的测试方面
- **失败原因分类**：失败用例的根本原因统计
- **趋势分析**：与历史执行的对比分析（如有数据）

#### 7.1.2 AI 失败分析卡片
针对每个失败用例提供详细分析：
- **问题严重程度**：高/中/低（不同颜色标识）
- **失败原因**：具体的根本原因分析
- **问题分类**：定位问题、断言问题、超时问题、网络问题等
- **疑似位置**：代码文件和行号（从堆栈中提取）
- **修复建议**：具体的代码修改或配置调整建议
- **置信度**：分析结果的可靠程度（0-1）
- **分析来源**：AI分析/服务错误/本地规则/已禁用

#### 7.1.3 测试结果表格增强
- **AI 分析列**：显示失败原因摘要
- **鼠标悬停**：显示完整分析详情（严重程度、分类、置信度）
- **状态标识**：不同状态的颜色标识（通过/失败/错误）

#### 7.1.4 报告数据文件
每次执行同时生成 JSON 格式的结构化数据文件，包含：
- 完整的测试结果数据
- AI 分析结果（含所有结构化字段）
- 执行统计信息
- 可用于后续分析或集成到其他系统

如需手动指定路径，也仍然支持：

```powershell
pytest ecommerce-autotest/testcases/test_login.py -vv --html=reports/html/custom_login.html --self-contained-html
```

## 9. 常见问题排查

### 9.1 服务未启动

先确认以下地址可访问：

- `http://localhost:3000`
- `http://localhost:8083/actuator/health`

### 9.2 配置不正确

重点检查：

- [config.yaml](/f:/Desk/graduation project/ecommerce-autotest/config/config.yaml)
- [login.yaml](/f:/Desk/graduation project/ecommerce-autotest/config/testdata/login.yaml)
- [ai_assistant.yaml](/f:/Desk/graduation project/ecommerce-autotest/config/testdata/ai_assistant.yaml)

### 9.3 浏览器驱动异常

当前默认使用 Chrome。若浏览器版本和驱动版本不匹配，可能导致启动失败。

### 9.4 页面定位器失效

如果报错属于以下类型，通常优先排查页面元素定位是否需要适配：

- `NoSuchElementException`
- `TimeoutException`
- `ElementClickInterceptedException`
- `element not interactable`

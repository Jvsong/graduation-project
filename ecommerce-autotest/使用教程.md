# 电商后台管理系统自动化测试框架使用教程

## 项目简介

电商后台管理系统自动化测试框架是一个基于 Python + Selenium 的自动化测试解决方案，专门为电商后台管理系统设计。它提供了完整的测试用例管理、执行控制、报告生成和日志记录功能，帮助测试团队高效地进行回归测试和功能验证。

### 主要特性

- **模块化设计**：采用页面对象模型（Page Object Model），代码结构清晰，易于维护
- **多浏览器支持**：支持 Chrome、Firefox、Edge 等主流浏览器
- **并行执行**：支持多进程并行执行测试，提高测试效率
- **智能报告**：自动生成美观的 HTML 测试报告，支持截图嵌入
- **邮件通知**：测试完成后可自动发送邮件报告
- **日志系统**：详细的执行日志记录，便于问题排查
- **配置灵活**：通过 YAML 配置文件管理测试环境和参数

### 系统要求

- Python 3.8+
- 浏览器：Chrome 90+ / Firefox 88+ / Edge 90+
- 操作系统：Windows 10/11、macOS 10.15+、Linux Ubuntu 20.04+

## 快速开始

### 1. 获取项目代码

```bash
# 克隆项目（如果是从版本库获取）
git clone <项目地址>
cd ecommerce-autotest
```

### 2. 环境准备

#### 安装 Python 依赖

```bash
# 创建虚拟环境（推荐）
python -m venv venv

# 激活虚拟环境
# Windows:
venv\Scripts\activate

# 安装依赖包
pip install -r requirements.txt
```

#### 安装浏览器驱动

项目提供了自动安装浏览器驱动的功能：

```bash
# 运行驱动安装脚本
python run.py --install-drivers
```

或者手动下载浏览器驱动：

1. **ChromeDriver**: [https://chromedriver.chromium.org/](https://chromedriver.chromium.org/)
2. **GeckoDriver (Firefox)**: [https://github.com/mozilla/geckodriver](https://github.com/mozilla/geckodriver)
3. **EdgeDriver**: [https://developer.microsoft.com/en-us/microsoft-edge/tools/webdriver/](https://developer.microsoft.com/en-us/microsoft-edge/tools/webdriver/)

将下载的驱动文件放在 `config/browsers/` 目录下。

### 3. 配置文件设置

#### 基础配置

1. 复制配置文件模板：

```bash
# 如果 config/config.yaml 不存在，会自动从模板复制
python run.py --check
```

2. 编辑 `config/config.yaml` 文件：

```yaml
environment:
  base_url: "http://your-ecommerce-admin.com"  # 改为实际的电商后台地址
  test_env: "test"  # 测试环境：test/staging/prod

browser:
  name: "chrome"  # 浏览器类型：chrome/firefox/edge
  headless: false  # 是否使用无头模式
  window_size: "1920x1080"  # 浏览器窗口大小
```

#### 测试数据配置

在 `config/config.yaml` 的 `test_data` 部分配置测试账号：

```yaml
test_data:
  login:
    valid_users:
      - username: "admin"      # 管理员账号
        password: "your_password"
        role: "管理员"
      - username: "operator"   # 操作员账号
        password: "operator123"
        role: "操作员"
```

#### 邮件配置（可选）

如需邮件通知功能，配置 SMTP 设置：

```yaml
report:
  send_email: true
  email_config:
    smtp_server: "smtp.example.com"
    smtp_port: 587
    username: "your_email@example.com"
    password: "your_password"
    sender: "test@example.com"
    receivers: ["team@example.com"]
```

### 4. 环境检查

运行环境检查命令，确保所有配置正确：

```bash
python run.py --check
```

如果检查通过，会显示：
```
[OK] 环境和配置检查通过
```

## 查看测试结果

### 测试报告

测试执行完成后，会自动生成 HTML 格式的测试报告。报告保存在 `reports/` 目录下，按时间戳命名：

```
reports/
├── report_20260408_143022/    # 每次执行生成的报告目录
│   ├── test_report.html       # HTML测试报告
│   └── test_report.json       # JSON格式报告数据
└── history/                   # 历史报告归档
```

直接在浏览器中打开 `test_report.html` 文件查看详细结果。

### 执行日志

所有测试执行过程都会记录在日志文件中：

```
logs/
└── test.log                  # 主日志文件
```

日志内容包括：
- 测试步骤详细记录
- 操作时间戳
- 页面元素定位信息
- 断言结果记录
- 异常错误信息

### 失败截图

当测试用例失败时，会自动截取当前页面屏幕截图，保存在报告目录的 `screenshots/` 子目录中。

## 测试用例开发指南

### 创建新的测试用例

1. **在 pages 目录中创建页面类**（如果不存在）：

```python
# pages/new_module_page.py
from pages.base_page import BasePage

class NewModulePage(BasePage):
    """新模块页面"""
    
    def __init__(self, driver):
        super().__init__(driver)
        self.url_suffix = "/new_module"
        
    def do_something(self, param):
        """执行某个操作"""
        self.click_element("button#do_something")
        self.input_text("input#param", param)
        self.click_element("button#submit")
        return self.get_element_text("div#result")
```

2. **在 testcases 目录中创建测试类**：

```python
# testcases/test_new_module.py
import unittest
from pages.new_module_page import NewModulePage

class TestNewModule(unittest.TestCase):
    """新模块测试用例"""
    
    def setUp(self):
        """测试前置条件"""
        self.driver = self.create_driver()
        self.page = NewModulePage(self.driver)
        self.page.open()
        
    def test_basic_function(self):
        """测试基本功能"""
        result = self.page.do_something("test_param")
        self.assertEqual(result, "预期结果")
        
    def tearDown(self):
        """测试清理"""
        self.driver.quit()
```

3. **在 config.yaml 中添加测试数据**（如果需要）：

```yaml
test_data:
  new_module:
    test_cases:
      - param: "value1"
        expected: "result1"
      - param: "value2"
        expected: "result2"
```

### 使用测试标签

为测试用例添加标签，便于分类执行：

```python
import pytest

@pytest.mark.smoke
def test_critical_function():
    """冒烟测试：关键功能"""
    pass

@pytest.mark.regression
def test_regression_function():
    """回归测试：回归验证"""
    pass

@pytest.mark.slow
def test_complex_function():
    """耗时测试：复杂场景"""
    pass
```

运行带标签的测试：

```bash
# 运行冒烟测试
python run.py --run smoke

# 运行回归测试
python run.py --run regression
```

## 配置详解

### 浏览器配置

```yaml
browser:
  name: "chrome"           # 浏览器类型：chrome/firefox/edge
```

## 常见问题

### Q1: 运行测试时提示 "chromedriver" 未找到

**解决方案**：
1. 运行自动安装命令：`python run.py --install-drivers`
2. 手动下载对应版本的 ChromeDriver，放在 `config/browsers/` 目录下
3. 确保 Chrome 浏览器已安装，且版本与 ChromeDriver 匹配

### Q2: 测试过程中元素定位失败

**可能原因及解决方案**：
1. **页面加载太慢**：增加 `implicit_wait` 配置值
2. **元素定位器失效**：检查页面结构是否变化，更新定位器
3. **iframe 嵌套**：使用 `switch_to.frame()` 切换到正确的 iframe
4. **动态元素**：使用显式等待等待元素出现

### Q3: 测试报告未生成

**检查步骤**：
1. 确保 `reports/` 目录存在且有写入权限
2. 检查 pytest-html 插件是否安装：`pip list | grep pytest-html`
3. 查看日志文件 `logs/test.log` 中的错误信息

### Q4: 如何在不同环境中运行测试

**解决方案**：
1. 创建多个配置文件：`config-test.yaml`, `config-staging.yaml`, `config-prod.yaml`
2. 通过环境变量指定配置文件：

```bash
# Windows
set CONFIG_FILE=config-staging.yaml
python run.py --run all

# Linux/macOS
export CONFIG_FILE=config-staging.yaml
python run.py --run all
```

3. 修改 `config_manager.py` 支持环境变量配置

### Q5: 测试执行速度慢

**优化建议**：
1. 使用并行执行：`python run.py --run all --workers 4`
2. 启用无头模式：`python run.py --run all --headless`
3. 减少隐式等待时间，使用显式等待代替
4. 复用浏览器实例（需要修改测试框架）

## 最佳实践

### 1. 元素定位策略

- 优先使用 ID、name 等稳定属性
- 避免使用绝对 XPath，尽量使用相对定位
- 为重要元素添加 data-testid 属性，便于测试定位
- 使用页面对象模型封装元素定位器

### 2. 测试数据管理

- 测试数据与测试逻辑分离
- 使用配置文件管理测试数据
- 为不同环境准备不同的测试数据
- 测试后清理测试数据，避免污染

### 3. 测试用例设计

- 每个测试用例保持独立，不依赖其他用例
- 合理使用 setup 和 teardown 管理测试状态
- 为测试用例添加详细的注释和文档
- 使用参数化减少重复代码

### 4. 异常处理

- 添加合理的等待机制，处理网络延迟
- 使用 try-catch 处理预期异常
- 失败时自动截图，便于问题排查
- 记录详细的日志，便于追溯问题

### 5. 持续集成

- 将测试框架集成到 CI/CD 流水线中
- 设置定时执行任务，进行日常回归测试
- 测试失败时自动通知相关人员
- 定期清理旧的测试报告和日志
